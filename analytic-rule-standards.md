# Sentinel Baseline Analytic Rules Repository

---

## **Overview**

This repository maintains a **standardized, reusable set of Microsoft Sentinel analytic rules** for deployment across MSSP (Managed Security Service Provider) client environments.

These rules are designed to ensure:
- Consistent detection coverage across all clients  
- High-quality, behavior-based detections  
- Efficient onboarding and deployment into new workspaces  
- Alignment with MITRE ATT&CK and SOC operational standards  

---

## **Objective**

The primary goal of this repository is to provide a centrally governed, high-confidence detection baseline that can be deployed, maintained, and tuned across multiple customer environments.

This enables:
- Scalable SOC operations  
- Faster client onboarding  
- Consistent alert quality  
- Reduced false positives through standardized tuning  

---

## **Features**

#### Standardization
All analytic rules must adhere to:
- Defined YAML schema  
- Naming conventions  
- Required metadata fields  

---

### Behavioral Detection First

Rules should prioritize:
- Behavior-based detections  
- Identity, process, and control-plane activity  

Avoid over-reliance on static IoCs (IPs, domains) unless threat intelligence-driven.

---

<a href="https://crispy-adventure-zg7q214.pages.github.io/"><strong>MITRE ATT&CK Alignment</strong></a>
- Must map only to observed behavior  
- Must align with current MITRE ATT&CK version  
- Avoid over-mapping or inferred techniques  

---

### *SOC Usability*

Every rule must:
- Produce actionable alerts  
- Include investigation context (entities, enrichment)  
- Minimize noise  

---

### Reusability Across Clients

Rules must:
- Avoid tenant-specific hardcoding  
- Use watchlists, parameters, and dynamic logic

## **Analytic Rule Standards**
- ***Every rule MUST include:***

<span style="color:green; font-family:Consolas">id:</span>

- Unique identifier for the analytic rule. Ascent rules must start with **ASC-** followed by a valid UUID. Should be set once and will not be changed. Stays the same in all customer environments.
    - Example: <span style="color:skyblue; font-family:Consolas;">ASC-c3be583b-1589-4cbc-a4c2-77e164882779</span>

<span style="color:green; font-family:Consolas">name:</span>
- Name of the analytic rule. This will not be viewable in the GUI. Must be a non-empty string
    - Example: <span style="color:skyblue; font-family:Consolas">Use Of RMM Software Detected</span>

<span style="color:green; font-family:Consolas">severity:</span>
- Informational
- Low
- Medium
- High

<span style="color:green; font-family:Consolas">query:</span> <span style="color:lightpurple">|</span>
- KQL Develpment Standards must:
    - Use let statements for readability
    - Filter early (where TimeGenerated)
    - Avoid unnecessary joins
    - Use watchlists for: known good entities and allowlists
    - Include output shaping (|project TimeGenerated, Account, IPAddress, Resource)

<span style="color:green; font-family:Consolas">kind:</span>
- Type of rule. Must be either **Scheduled** or **NRT** (Near Real Time)

<span style="color:green; font-family:Consolas">displayName:</span>
- The name that will be displayed in Sentinel. Must be a non-empty string. This is what shows in the GUI.
    - Example: <span style="color:skyblue; font-family:Consolas">Use of RMM Software Detected</span>

<span style="color:green; font-family:Consolas">suppressionDuration:</span>
- The duration for which the alerts generated by this rule will be suppressed. Must be a valid ISO 8601 duration format.
    - Example: <span style="color:skyblue; font-family:Consolas">PT5M</span> = 5 minutes

- *ISO 8601 Format*

| Symbol | Meaning |
|--------|---------|
| P | Period (Required) |
| Y | Years |
| M | Months |
| D | Days |
| T | Time separator |
| H | Hours |
| M | Minutes (time section) |
| S | Seconds |

- Add *T* only when specifying time (hours, minutes, seconds)
- Quick Reference Guide:

| Use Case | Value |
|----------|-------|
| 30 seconds | PT30S |
| 5 minutes | PT5M |
| 1 hour | PT1H |
| 12 hours | PT12H |
| 1 day | P1D |
| 7 days | P7D|
| 1 Month | P1M |
| 1 Year | P1Y|  

<span style="color:green; font-family:Consolas">suppressionEnabled:</span>
- Indicates if suppression is enabled. Must be Boolean value (true or false).

<span style="color:green; font-family:Consolas">queryFrequency:</span>
- How often the query runs. Must be a valid ISO 8601 duration format.
    - Example: <span style="color:skyblue; font-family:Consolas">P1D</span> (Period of 1 Day)

<span style="color:green; font-family:Consolas">queryPeriod:</span>
- Time span that data looks back. Must be a valid ISO 8601 duration format.
    - Example: <span style="color:skyblue; font-family:Consolas">P7D</span> (Period of 7 Days)

<span style="color:green; font-family:Consolas">triggerOperator:</span>
- Operation used for the trigger threshold. Must be one of the following:
    - GreaterThan, LessThan, EqualTo, NotEqualTo

<span style="color:green; font-family:Consolas">triggerThreshold:</span>
- The threshold for triggering an alert. Can not be a negative number (0 or more).

<span style="color:green; font-family:Consolas">enabled:</span>
- Indicates if the rule is enabled or disabled. Must be in Boolean value (enabled or disabled).

<span style="color:green; font-family:Consolas">startTimeUtc:</span>

<span style="color:green; format-family:Consolas">alertDetalsOverride:</span>
- Template for settings on how to dynamically override alert static details.

<span style="color:green; font-family:Consolas;">customDetails:</span>  
&nbsp;&nbsp;&nbsp;&nbsp;<span style="color:green; font-family:Consolas;">MitreTactics:</span> <span style="color:skyblue; font-family:Consolas;">Tactics</span>

<span style="color:green; font-family:Consolas">description:</span> <span style="color:lightpurple">|</span>

This is an "Alert Only" rule that is used with alert chaining to create higher fidelity alerts. Use the accompanying watchlist to filter known approved RMM software in the environment.'</span>

### Example: Complete Analytic Rule

```yaml
id: ASC-c3be583b-1589-4cbc-a4c2-77e164882779
name: Use Of RMM Software Detected
severity: Medium
query: |
  let watchlist = materialize(
      _GetWatchlist("UseOfRMMSoftwareDetected")
      | where datetime_add('day', toint(Expiration_in_days), LastUpdatedTimeUTC) > now()
      | summarize Values = make_set(Value) by Type
      );
  let watch_RMM = (
      watchlist
      | where Type == "RMM"
      | project Values
      );
  let watch_host = (
      watchlist
      | where Type == "HOST"
      | project Values
      );
  let watch_account = (
      watchlist
      | where Type == "ACCOUNT"
      | project Values
      );
  let Lookback = 30m;
  let SuppressionTime = 3h;
  let SuppressedAlertName = "Use Of RMM Software Detected";
  let RMMList = externaldata(FileName:string)
      ['https://lolrmm.io/api/rmm_tools.csv']
      with (format='csv', ignoreFirstRecord=true)
      | extend FileName = replace_regex(tolower(FileName), @"[^a-z0-9]", "");
  let Current =
      DeviceProcessEvents
      | where TimeGenerated >= ago(Lookback)
      | where FileName has_any (RMMList)
      | extend UserAccount = tolower(split(tostring(AccountUpn), "@")[0])
      | extend HostName = tolower(split(tostring(DeviceName), ".")[0])
      | project
          RMMTime = TimeGenerated,
          HostName,
          FileName,
          FolderPath,
          ProcessCommandLine,
          UserAccount;
  let PriorAccountHostPairs =
      SecurityAlert
      | where TimeGenerated >= ago(SuppressionTime)
      | where AlertName has SuppressedAlertName
      | extend EntityList = parse_json(Entities)
      | mv-expand Entity = EntityList
      | extend EntityType = tostring(Entity.Type)
      | extend Account = iff(EntityType == "account", replace_string(trim(" ", tolower(tostring(Entity.Name))), " ", ""), "")
      | extend Host = iff(EntityType == "host", trim(" ", tolower(split(tostring(Entity.HostName), ".")[0])), "")
      | summarize Accounts = make_set(Account), Hosts = make_set(Host) by SystemAlertId
      | mv-expand Accounts
      | mv-expand Hosts
      | where Accounts != "" or Hosts != ""
      | extend AccountHostKey = strcat(Accounts, "|", Hosts)
      | distinct AccountHostKey;
  Current
      | extend AccountHostKey = strcat(UserAccount, "|", HostName)
      | join kind=leftanti PriorAccountHostPairs on AccountHostKey
      | summarize arg_min(RMMTime, *) by HostName, UserAccount
      | project RMMTime, HostName, FileName, FolderPath, ProcessCommandLine, UserAccount, Tactics, Techniques
      | extend Techniques = dynamic(["T1219"])
      | extend Tactics = dynamic(["CommandAndControl"])
      | where FileName !in (watch_RMM) and HostName !in (watch_host) and UserAccount !in (watch_account)
