# Sentinel Baseline Analytic Rules Repository

---

## **Overview**

This repository maintains a **standardized, reusable set of Microsoft Sentinel analytic rules** for deployment across MSSP (Managed Security Service Provider) client environments.

These rules are designed to ensure:
- Consistent detection coverage across all clients  
- High-quality, behavior-based detections  
- Efficient onboarding and deployment into new workspaces  
- Alignment with MITRE ATT&CK and SOC operational standards  

---

## **Objective**

The primary goal of this repository is to provide a centrally governed, high-confidence detection baseline that can be deployed, maintained, and tuned across multiple customer environments.

This enables:
- Scalable SOC operations  
- Faster client onboarding  
- Consistent alert quality  
- Reduced false positives through standardized tuning  

---

## **Features**

#### Standardization
All analytic rules must adhere to:
- Defined YAML schema  
- Naming conventions  
- Required metadata fields  

---

### Behavioral Detection First

Rules should prioritize:
- Behavior-based detections  
- Identity, process, and control-plane activity  

Avoid over-reliance on static IoCs (IPs, domains) unless threat intelligence-driven.

## Analytic Rule Standards

**Every rule MUST include:**

---

### ID
- Unique identifier for the analytic rule. Must start with **ASC-** followed by a valid UUID. Should be set once and never changed. Consistent across all customer environments.  
```yaml
id: ASC-c3be583b-1589-4cbc-a4c2-77e164882779
```
### Name
- Name of the analytic rule. This will not be viewable in the GUI. Must be a non-empty string.
```yaml
name: Use of RMM Software Detected
```
### Severity
- Informational
- Low
- Medium
- High
```yaml
severity: Medium
```
### Query
- KQL Development Standards must:
      - Use let statements for redability
      - Filter early (| where TimeGenerated)
      - Avoid unnecessary joins
      - Use watchlists for known good entities and allowlists
      - Include output shaping (| project TimeGenerated, Account, IPAddress, Resource)
```yaml
query: |
```
### Kind
- Type of rule. Must be either 'Scheduled' or 'NRT' (Near Real Time)
```yaml
kind: Scheduled
```
### Display Name
- The name that will be displayed in Sentinel. Must be a non-empty string. This is what shows in the GUI.
```yaml
dispalyName: Use of RMM Software Detected
```
### Suppression Duration
- The duration for which the alerts generated by this rule will be suppressed. Must be in valid ISO 8601 duration format.
```yaml
suppressionDuration: PT5M
```
### ISO 8601 Format  
| Symbol | Meaning |
|--------|---------|
| P | Period (Required) |
| Y | Years |
| M | Months |
| D | Days |
| T | Time Separator |
| H | Hours |
| M | Minutes |
| S | Seconds |
- Add 'T' only when specifying time (hours/minutes/seconds)

### Quick Reference Guide
| Use Case | Value |
|----------|-------|
| 30 seconds | PT30S |
| 5 minutes | PT5M |
| 1 hour | PT1H |
| 12 hours | PT12H |
| 3 days | P3D |

### Suppression Enabled
- Indicates if suppression is enabled. Must be a Boolean value (true or false).
```yaml
suppressionEnabled: false
``` 
### Query Frequency
- How often the query runs. Must be a valid ISO 8601 duration format.
```yaml
queryFrequency: P1D
```
### Query Period
- Time span the data looks back. Must be a valid IOS duration format.
```yaml
queryPeriod: PT3H
```
### Trigger Operator
- Operator used for the trigger threshold. Must be one of the following:
      - GreaterThan
      - LessThan
      - EqualTo
      - NotEqualTo
```yaml
triggerOperator: GreaterThan
```
### Trigger Threshold
- The threshold for triggering an alert. Can not be a negative number (0 or greater).
```yaml
triggerThreshold: 0
```
### Enabled
- Indicates if the rule is enabled. Must be Boolean value (true or false).
```yaml
enabled: true
```
### Start Time UTC
- Used to define when an analytic rule begins running, ensuring detections start at a controlled, intended point in time rather than immediately upon deployment.
```yaml
startTimeUtc:
```
### Alert Details Override
- Used to dynamically override static alert details with contextual information from query results.
```yaml
alertDetailsOverride:
```
### Custom Details
- These fields ensure the analytic rule aligns directly with the query logic and accurately reflects the adversary behavior being detected.
```yaml
customDetails:
    MitreTactics: Tactics
    MitreTechniques: Techniques
```
### Alert Rule Template Name
- This must match the ID without **ASC-**
```yaml
alertRuleTemplateName: c3be583b-1589-4cbc-a4c2-77e164882779
```
### Description
- Defines the alert description format, allowing dynamic values from query results to populate the alert details. Must be a valid string.
```yaml
description: |
    'This alert detects the use of RMM software in a customer environment. This is an alert only rule that is used with alert chaining to create higher
  fidelity alerts. Use the accompanying watchlist to filter known approved RMM software in the environment.'
```
### Status
- Indicates the lifecycle state of the rule, such as whether it is available, disabled, or in development. 
```yaml
status: Available
```
### Required Data Connectors
- Defines the data connectors required for the analytic rule to function. Must include valid connector IDs and associated data types.
```yaml
requiredDataConnectors:
    - connectorId: MicrosoftThreatProtection
      dataTypes:
        - DeviceProcessEvents
```
### Tactics
- Valid MITRE ATT&CK tactics covered by this rule. Must be valid tactic name(s).
```yaml
tactics:
  - CommandAndControl
```
### Relevant Techniques
- Valid MITRE ATT&CK techniques covered by this rule. Must be valid technique(s)
```yaml
relevantTechniques:
  - T1219
```
### Tags
- Optional labels used to categorize and organize the analytic rule for easier identification and filtering.
```yaml
tags:
```
### Entity Mapping
- Defines the mapping standards for entities, ensuring they are accurately typed and correctly aligned to their corresponding identifiers.
```yaml
entitiyMappings:
    - entityType: File
      fieldMappings:
        - identifier: Name
          columnName: FileName
    - entityType: Host
      fieldMappings:
        - identifier: HostName
          columnName: HostName
    - entityType: Account
      fileMappings:
        - identifier: Name
          columnName: UserAccount
```
### Sentinel Entity Mapping
- Maps query results to Sentinel entities to enable visualization, correlation, and investigation within alerts and incidents.  
### Version
- Specifies the version of the rule using a valid versioning format. For Microsoft (MSFT) templates, the version must be less than or equal to the current template version.
```yaml
sentinelEntitiesMappings:
version: 1.0.3
```
### Event Group Settings
- Defines how multiple events are grouped into alerts, controlling aggregation behavior and alert generation logic.  
### Aggregation Kind
- Defines how alerts are grouped, determining whether each event generates a separate alert or multiple events are combined into a single alert. (AlertPerResult or SingleAlert)
```yaml
eventGroupingSettings:
    aggregattionKind: SingleAlert
```
### Incident Configuration:
- Specifies whether alerts generated by the analytic rule will create incidents and defines how those incidents are grouped and managed.
```yaml
incidentConfiguration:
    createIncident: false
    groupingCongifiguration:
      enabled: false
      repoenClosedIncident: false
      groupByAlertDetails: []
      groupByCustomDetails: []
      groupByEntities: []
      lookbackDuration: PT5H
      MatchingMethod: AllEntities
```
### Review
- Indicates whether the rule has been reviewed and validated for accuracy, performance, and intended behavior. Should be set to a Boolean value (true or false), but may be left unset if not yet evaluated.
```yaml
review:
```
### Score
- Represents the relative impact or priority of the rule based on associated MITRE ATT&CK techniques. Must be 0 or higher. Can be used to reflect the combined threat score from relevant techniques within a MITRE Navigator Threat Layer.
```yaml
score: 0
```
### Alerts Per Day / Alerts Per Week
- Tracks the average number of alerts generated by the rule on a daily and weekly basis. Must be non-negative float values and can be used to measure rule performance and efficiency.
```yaml
alertsPerDay: 0.0
alertsPerWeek: 0.0
```
### Notes / Use
- Optional fields for additional context, usage guidance, or operational notes related to the rule.
### MetaData
- Provides information about the rule, including authorship, ownership, and support details. Should include at minimum source and support. Maintain attribution when a rule is derived from another source. Give credit where credit is due.
```yaml
notes:
use:
metadata:
    source:
      kind: Ascent Solutions
    author:
      name: Michael Hemming
    support:
      tier: Ascent Solutions
    categories
```

### Example: Complete Analytic Rule

```yaml
id: ASC-c3be583b-1589-4cbc-a4c2-77e164882779
name: Use Of RMM Software Detected
severity: Medium
query: |
  let watchlist = materialize(
      _GetWatchlist("UseOfRMMSoftwareDetected")
      | where datetime_add('day', toint(Expiration_in_days), LastUpdatedTimeUTC) > now()
      | summarize Values = make_set(Value) by Type
      );
  let watch_RMM = (
      watchlist
      | where Type == "RMM"
      | project Values
      );
  let watch_host = (
      watchlist
      | where Type == "HOST"
      | project Values
      );
  let watch_account = (
      watchlist
      | where Type == "ACCOUNT"
      | project Values
      );
  let Lookback = 30m;
  let SuppressionTime = 3h;
  let SuppressedAlertName = "Use Of RMM Software Detected";
  let RMMList = externaldata(FileName:string)
      ['https://lolrmm.io/api/rmm_tools.csv']
      with (format='csv', ignoreFirstRecord=true)
      | extend FileName = replace_regex(tolower(FileName), @"[^a-z0-9]", "");
  let Current =
      DeviceProcessEvents
      | where TimeGenerated >= ago(Lookback)
      | where FileName has_any (RMMList)
      | extend UserAccount = tolower(split(tostring(AccountUpn), "@")[0])
      | extend HostName = tolower(split(tostring(DeviceName), ".")[0])
      | project
          RMMTime = TimeGenerated,
          HostName,
          FileName,
          FolderPath,
          ProcessCommandLine,
          UserAccount;
  let PriorAccountHostPairs =
      SecurityAlert
      | where TimeGenerated >= ago(SuppressionTime)
      | where AlertName has SuppressedAlertName
      | extend EntityList = parse_json(Entities)
      | mv-expand Entity = EntityList
      | extend EntityType = tostring(Entity.Type)
      | extend Account = iff(EntityType == "account", replace_string(trim(" ", tolower(tostring(Entity.Name))), " ", ""), "")
      | extend Host = iff(EntityType == "host", trim(" ", tolower(split(tostring(Entity.HostName), ".")[0])), "")
      | summarize Accounts = make_set(Account), Hosts = make_set(Host) by SystemAlertId
      | mv-expand Accounts
      | mv-expand Hosts
      | where Accounts != "" or Hosts != ""
      | extend AccountHostKey = strcat(Accounts, "|", Hosts)
      | distinct AccountHostKey;
  Current
      | extend AccountHostKey = strcat(UserAccount, "|", HostName)
      | join kind=leftanti PriorAccountHostPairs on AccountHostKey
      | summarize arg_min(RMMTime, *) by HostName, UserAccount
      | project RMMTime, HostName, FileName, FolderPath, ProcessCommandLine, UserAccount, Tactics, Techniques
      | extend Techniques = dynamic(["T1219"])
      | extend Tactics = dynamic(["CommandAndControl"])
      | where FileName !in (watch_RMM) and HostName !in (watch_host) and UserAccount !in (watch_account)
kind: Scheduled
displayName: Use Of RMM Software Detected
suppressionDuration: PT5M
suppressionEnabled: false
queryFrequency: PT30M
queryPeriod: PT3H
triggerOperator: GreaterThan
triggerThreshold: 0
enabled: true
startTimeUtc:
alertDetailsOverride:
customDetails:

alertRuleTemplateName: c3be583b-1589-4cbc-a4c2-77e164882779
description: |
